# Deep Research Lite

[English](README.md)

一个面向个人 Codex 与工具型 Agent 用户的低成本、证据可追溯研究 Skill。

Deep Research Lite 保留长程研究 Agent 中最有价值的方法，但不再默认认为每个任务都值得大量搜索、多 Agent、独立 Writer 和额外 Reviewer。

## v1.1 的主要变化

本版本针对个人用户的 token、API、上下文和本地算力成本进行了收敛：

- **Instant / Research / Deep** 三档运行模式
- 默认单 Agent 执行
- 软性工具调用与研究预算
- 每次继续检索前进行“预期信息价值”判断
- 普通任务使用紧凑证据记录
- 只有方法学与适用性关键时才启用完整证据账本
- Research 模式默认不调用独立停止审查者
- 独立 Auditor 与并行分支保留给 Deep 模式
- 当继续研究不太可能改变答案时，按成本收益停止

目标不是把研究做浅，而是把 token 花在真正可能改变结论、置信度或下一步行动的位置。

## 工作模式

| 模式 | 适用场景 | 默认行为 |
|---|---|---|
| **Instant** | 聚焦的时效问题、单点核查 | 1–5 次工具调用，不建账本，不启用 Auditor |
| **Research** | 仓库审核、论文比较、政策与技术分析 | 单 Agent、紧凑证据，通常 4–10 次高价值工具调用 |
| **Deep** | 用户明确要求穷尽式研究，或高风险多独立分支任务 | 完整证据账本、选择性并行、独立停止审查 |

这些限制是软预算。当关键不确定性、矛盾或缺失的一级来源确实值得继续验证时，可以有理由地超过预算。

## 核心流程

```text
冻结小型研究契约
→ 建立完成任务所需的最小问题树
→ 优先检索信息价值最高的证据
→ 维护紧凑的结论—证据记录
→ 按风险执行反证检查
→ 当下一步不太可能改变答案时停止
→ 只综合用户真正需要的内容
```

## 成本控制原则

- 证据质量高于来源数量。
- 十家媒体重复同一公告，只算一条证据链。
- 搜索结果摘要用于发现来源，不能自动充当最终证据。
- 额外检索应有可能改变答案、置信度或建议。
- Checkpoint 节省的上下文必须多于它本身消耗的 token。
- 并行 Agent 不应重复研究同一问题。
- 独立 Auditor 是 Deep 模式的成本，不是默认仪式。
- token、工具或时间耗尽必须标记为部分完成，不能伪装成成功。

## 防止过早停止

成本控制不等于允许无证据结论。

Instant 与 Research 模式采用紧凑、可机械检查的完成条件。Deep 模式才增加结构化 `STOP_REPORT`、独立反向审查者和硬性 blocker 校验。

通用阻止条件包括：

- 关键交付项仍未回答
- 核心结论无证据或只依赖搜索摘要
- 隐藏关键矛盾或证据缺口
- 在需要时未进行反证检查
- 擅自缩小原始研究契约
- 隐藏来源无法访问的问题
- 把 token 或工具耗尽误认为任务完成

## 安装

将 `SKILL.md` 复制到 Agent 平台的 Skill 目录，或通过宿主平台的指令加载机制引入。

```bash
mkdir -p ~/.agent/skills/deep-research-lite
cp SKILL.md ~/.agent/skills/deep-research-lite/SKILL.md
```

具体目录取决于宿主平台。

## 个人 Codex 用户的建议用法

- 聚焦的版本核查、事实查询或单仓库问题使用 **Instant**。
- 大多数认真仓库分析、技术比较和有来源的推荐使用 **Research**。
- 只有用户明确要求穷尽式工作，或多个高风险独立分支值得额外成本时，才使用 **Deep**。
- 除非分支真正独立，否则保持单 Agent。
- 优先查看官方文档、仓库文件、论文、监管文件、公司披露或原始数据，不要先阅读大量二手摘要。
- 某个来源持续无法访问时，宁可输出部分完成结果，也不要无限消耗 token。

## 能力边界

本仓库提供的是研究编排 Skill，而不是经过专门训练的 Deep Research 模型。它不能复制专用研究模型的内在能力或 benchmark 表现。
